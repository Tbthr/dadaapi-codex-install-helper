# Security Rules

- 开源客户端中的固定密钥不能视为秘密。
- 订阅数据只通过 Gitee/GitHub Raw HTTPS 静态文件传递，不得通过 HTTP、URL 查询参数或日志传递。
- 客户端不得跳过 Gitee 或 GitHub TLS 验证，也不得在验证失败后降级到 HTTP。
- Ed25519 签名和 SHA-256 用于确认来源及完整性，XChaCha20-Poly1305 用于避免在公开仓库中直接浏览节点正文。
- 客户端缓存只保存原始签名清单、签名和加密路由，每次读取必须重新验签、重新校验、重新解密并检查有效期。
- 路由签名私钥和原始上游订阅地址只能存在于独立路由仓库的 GitHub Actions Secrets。
- 日志中的 URL 必须隐藏用户名、密码、Token 和查询参数。
- 静态路由请求错误只能记录超时、连接、状态码、大小限制等分类，不得附带 reqwest 原始 URL 错误文本。
- `manifest.json` 只能包含版本、时间、密文文件名、大小、哈希、加密算法和 `keyId`，不得包含上游订阅 URL、查询 Token 或节点凭据。
- 节点凭据只允许存在于客户端运行内存中，不写入磁盘缓存、日志、错误信息或遥测。
- `route-e2e` 通过当前用户私有文件读取公钥和解密 key，不得将 key 放入命令行参数、输出、日志或测试 fixture。
- 下载地址必须来自客户端内置可信官方目录，并逐跳限制 HTTPS 重定向主机。
- 下载任务持久化不得保存或信任任意目标路径；目标文件必须由可信产品目录重新计算。
- 安装器打开命令只能使用可信产品目录解析出的官方下载文件和后端计算的本地路径，不能接受前端传入的任意路径、命令或参数。
- 桌面客户端不创建本地文件日志，也不提供诊断报告或导出功能。
- 不执行服务器下发的任意 shell 命令。
- 静态路由仓库只能发布签名清单、签名和加密路由，不下发脚本或可执行指令。
- 修改系统代理前写入恢复记录，恢复操作必须幂等。
- 激活后的恢复操作只能由用户在界面中明确触发；启动时不得自动改写代理设置。
- 临时系统代理只能指向本机回环地址；恢复记录不得写入日志，且必须使用当前用户私有权限保存。
- 无法读取并完整恢复的认证代理配置必须阻止激活，不能用不完整状态覆盖用户原配置。
- 前端不得获得不必要的 Tauri capability。
